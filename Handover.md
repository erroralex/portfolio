# Handover

## Overview
This document tracks recent changes, current context, and next steps for the Developer Portfolio SPA project.

## Recent Changes
- Reworked the top nav to match the button/contact-card "top-glow" hover treatment: each `.nav-link` now gets a permanent thin outline (`--color-border-default`, matching `.btn-outline`) plus a top gradient glow line that fades in on hover and stays on for `.nav-link.active`. Colors alternate teal / violet / blend across the five links via `--c-accent` on `li:nth-of-type(3n+1/2/3)`, the same pattern already used for `.contact-link` and `.project-card`.
- Fixed the glow rendering: `.nav-link` needed `overflow: hidden` (like `.btn` already has) so the glow's square corners clip to the pill's rounded border instead of poking past it; a stale `@media (min-width: 860px) { .site-nav .nav-link { border-bottom: none; } }` reset (leftover from before the border existed) was zeroing out the bottom edge of the desktop pill outline and has been removed.
- Fixed the mobile dropdown menu: giving `.nav-link` a permanent border initially caused every mobile row to show a boxed outline instead of a clean divider list. `.site-nav.is-open .nav-link` now explicitly resets `border: none` before re-applying its own `border-bottom` divider.
- Fixed the mobile menu's glow position: on mobile the `<a>` is a full-width block, so the old percentage-based glow (`left: 18%; right: 18%`) centered over the whole row instead of the word. Each nav label is now wrapped in `<span class="nav-link-text">`; on mobile the row-wide glow is disabled and a new one is drawn on the text span itself (sized to the word, offset up by the row's padding-top so it still sits on the row's top edge).
- Rewrote the scrollspy in `script.js`: the old `IntersectionObserver` with a shrunk `rootMargin` band unreliably activated the tall Projects section and never activated Contact (the last section can't scroll far enough to enter the shrunk band). Replaced with a scroll-position check that walks sections top-to-bottom and marks the last one whose top has crossed the header offset as active, plus an explicit "scrolled to bottom of page" check for the last section.
- Brightened `--color-text-tertiary` from `#6B6E78` to `#8A8D97` after a full contrast audit found it failing WCAG AA (3.6-3.9:1) everywhere it's used (about.json filename, project tech line, download counter, "Private repo" label, timeline org, footer copyright). Verified all six usages now clear 4.5:1 (4.60:1 in the tightest case, the about.json titlebar).
- Ran a full accessibility/broken-link audit (see conversation for the complete report): no dead links or missing assets found; heading order, landmarks, skip-link, focus-visible, and keyboard/focus-trap behavior are all correct; one open item remains below (Tech Stack icon images can shift layout on load).
- Verified all of the above by installing Playwright locally and screenshotting the real rendered nav (desktop pill outline/glow, mobile dropdown open/hover/active states) rather than relying on static analysis alone.

## Next Steps
- Push a new version tag (e.g. `v1.1.1`) to trigger the GitHub Actions deployment for this batch of nav/accessibility fixes.
- Add explicit `width`/`height` (or a CSS `aspect-ratio`) to the Tech Stack cards' multi-icon images (`.stack-card img`, the skillicons.dev rows) — they're the one remaining image type with no reserved space, so they can still shift the grid on load.
- Make the `wiggy`, `drop-in-brain`, and `Lo-Fi-AI` repos public if/when ready, then re-add their "Code on GitHub" links (and a real screenshot for Drop-in Brain, which currently doesn't have one).
- Perform a manual pass on a real device/browser for final polish: the projects grid at various breakpoints, the timeline glow animation (mask-image/`mix-blend-mode: screen` support varies slightly across engines), and the download counters (GitHub's unauthenticated API is rate-limited to 60 req/hr per IP; fine for normal traffic but worth knowing about).
